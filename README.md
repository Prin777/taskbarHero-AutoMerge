# TBH 自动合成工具

这是一个面向 Windows 11 的《TBH: Task Bar Hero》本地鼠标自动化工具。当前版本为 `0.4.6`，只处理“装备”和“材料”，不读取游戏进程、存档或网络数据。

## 功能概览

- 程序启动后立即执行一轮，之后每隔 5 小时执行。
- 只识别合成按钮是否为蓝色高亮，不再识别九宫格内容。
- 自动处理“装备”和“材料”，不处理“饰品”，合成优先级沿用游戏内置逻辑。
- 按进程名和 Unity 窗口类型自动找到游戏，必要时自动激活游戏。
- 自动用 `Tab` 打开英雄背包，识别并点击黄色魔方入口，再识别全部合成按钮位置。
- 支持全自动识别、手动校准、F8 暂停/恢复、F9 紧急停止。
- 自动识别失败时保存现场截图，运行过程记录各格图像差异值。

## 使用前提

- Windows 11。
- 游戏使用简体中文界面。
- 自动化运行期间，游戏窗口大小和界面比例应与校准时一致。
- 从源码运行或自行构建需要 Python 3.11 或更高版本。

## 当前行为

- 程序启动或首次校准完成后立即执行一轮，不检查背包是否已满。
- 不检测也不修改“包含仓库物品”，直接执行合成。
- 依次处理“装备”和“材料”，不处理“饰品”。
- 每个类别执行以下流程：
  1. 点击“自动填充”。
  2. 等待最多 3 秒，并连续两次确认合成按钮为蓝色高亮后才点击合成。
  3. 若按钮一直为灰色，点击左侧退回按钮，再次自动填充复核。
  4. 第二次按钮仍为灰色，则再次退回物品，并判定当前类别处理完毕。
- 两个类别都完成后等待 5 小时，再开始下一轮。5 小时从上一轮完成时开始计算。
- 每轮会自动查找已校准的游戏窗口、打开背包和魔方，并刷新全部按钮位置。
- 仅在进程名、Unity 窗口类型、窗口尺寸均符合且目标位置未被遮挡时点击。
- 单类别每轮最多合成 100 次，超时或异常会自动暂停，避免死循环。

## 快捷键与状态

- `F8`：开启或暂停托管。
- `F9`：紧急停止并取消当前一轮。
- “立即执行”：忽略剩余倒计时，开始新一轮。
- 状态窗口会显示托管中、等待游戏、暂停、异常和下一轮倒计时。

程序到期后会主动找到并短暂激活游戏，以便打开界面、截图和执行操作。找不到游戏时会保持等待；发现窗口尺寸或显示缩放变化时会安全暂停并要求重新识别。每次点击前仍会复核游戏是否位于前台以及目标点是否被遮挡。

如果快捷键被其他程序占用，状态窗口会显示红色警告。校准时仍可使用“3 秒后捕获鼠标位置”按钮；F9 注册失败时不要进行无人值守运行，应先关闭占用快捷键的程序并重启本工具。

## 自动识别位置

首次启动会优先打开自动识别。现在只需确保：

1. `TaskBarHero.exe` 正在运行；
2. 游戏使用简体中文界面；
3. 游戏操作区域没有无法移开的系统级遮挡。

确认后，工具会隐藏并按 `TaskBarHero.exe + UnityWndClass` 自动找到游戏。若魔方合成窗口尚未显示，程序会先在当前画面寻找黄色魔方入口；英雄背包尚未打开时才发送一次 `Tab`，随后识别并点击唯一的黄色魔方图标。看到“自动填充”后，程序按界面比例推导自动填充、类别菜单、合成和退回按钮的位置并保存。若检测到终端等窗口遮挡游戏，识别期间会临时把游戏置于最上层，采集完成后恢复；任何一步置信度不足、出现多个相似入口或目标被遮挡时都不会继续点击。失败现场与阶段截图保存在程序运行目录下的 `diagnostics\日期时间\`。

## 诊断资料

程序运行目录会生成可轮换的 `automation.log`。每次启动还会建立独立的 `diagnostics\日期时间\` 目录，其中包含本次会话日志、自动识别各阶段的完整客户区截图，以及合成按钮状态截图。自动识别失败时，弹窗会显示本次诊断目录；排查问题时请直接打包该目录，不要只复制错误弹窗。

阶段截图按执行顺序命名，例如：

```text
auto-detect-initial.bmp           初始游戏画面
auto-detect-after-tab.bmp         按 Tab 打开英雄背包后
auto-detect-after-cube-click.bmp  点击黄色魔方入口后
```

日志同时记录程序版本、Python 与 Windows 版本、游戏客户区尺寸、屏幕分辨率、窗口 DPI、显示缩放，以及黄色候选区域的接受或淘汰原因。若程序运行目录不可写，日志与诊断资料会回退到 `%LOCALAPPDATA%\TaskbarHeroAutoSynth\`。

## 合成按钮识别原理

程序不再读取九宫格，也不保存空格截图基准。点击自动填充后，先等待 0.65 秒，再在合成按钮中心持续采集 `32×32` 像素区域。蓝/青色像素比例达到 25% 时视为蓝色高亮，并且必须连续两次通过才允许点击。

```text
蓝色像素比例 >= 25%，连续两次：允许合成
等待 3 秒仍未连续通过：按钮不可用
```

点击动作前还会立即再采样一次，防止按钮在鼠标按下前变回灰色。第一次等待后按钮仍不可用时会退回物品并重新自动填充，第二次仍不可用才结束当前类别。点击合成后等待 2.5 秒，再开始下一次自动填充。

## 手动校准

点击“手动校准”，按照向导依次把鼠标放到指定位置并按 `F7`。类别菜单项校准时，需要手动点开下拉菜单。校准配置保存在：

```text
%LOCALAPPDATA%\TaskbarHeroAutoSynth\config.json
```

两台电脑可以分别使用自动识别；识别失败时再手动校准。游戏窗口可以移动，但改变窗口大小、Windows 显示缩放或游戏界面比例后需要重新识别。

0.2.3 版本增加了多比例、逐像素自动识别，避免大截图中按钮文字刚好位于奇数像素时被快速扫描跳过；同时取消了手动校准结束时容易误判的九格外观相似检查。升级后旧基准会自动失效，需要重新执行一次“自动识别位置”或“手动校准”。第 8 步捕获完成后会直接保存九个空格采样，不会再因为各格背景明暗不同而拒绝保存；因此捕获前仍要由用户确认九宫格确实为空。

0.2.4 版本修复了自动填充动画短暂显示 `9/9` 时过早点击，以及短暂低于九格时误判为合成成功的问题；同时增加合成点击重试、鼠标悬停等待和点击坐标日志。

0.2.5 版本将九格识别改为更大的采样区域和显著像素算法，改善普通品质装备识别；每次启动还会自动建立独立诊断目录，保存会话日志和关键九宫格截图。由于空格基准格式升级，首次使用 0.2.5 时必须重新校准一次。

0.2.6 版本修复了成功合成后仍反复识别旧九宫格并错误重试的问题，并在自动识别位置时主动处理其他窗口遮挡。

0.2.7 版本把合成按钮的蓝色高亮设为最终安全门：连续两次确认可用才点击，灰色按钮永不点击；九宫格识别结果保留为诊断信息，并可由游戏按钮状态纠正误报或漏报。

0.2.8 版本改为直接从游戏窗口客户区读取画面，避免置顶终端、透明悬浮窗等覆盖层污染九宫格和合成按钮截图。由于截图基准来源已经改变，升级后需重新执行一次自动识别或手动校准。

0.2.9 版本停用了会让 Unity 画面错位、裁掉魔方面板的离屏渲染方式，改为读取游戏客户区 DC，并拒绝黑屏、纯色和只绘制局部的无效截图。截图不再要求整个游戏窗口完全无遮挡；鼠标点击前仍会复核具体目标点。0.2.8 生成的错位基准会自动失效，需要重新校准。

0.2.10 版本针对 Unity 客户区 DC 返回空白的问题恢复实时桌面截图，但在每次采集前会真正激活、置顶并确认游戏为前台窗口，不再使用会让置顶终端继续覆盖游戏的“不激活”方式。0.2.9 未能完成的校准基准会自动失效。

0.2.11 版本会在截图期间临时降低实际覆盖游戏操作区的其他置顶窗口，结束后恢复；纯灰阶终端画面不再允许保存为九宫格基准。旧校准会作为正常配置迁移被清除并立即写回，不再每次启动打印异常堆栈，也不会丢失运行间隔等其他设置。

0.2.12 版本修复了 Windows 显示缩放大于 100% 时的坐标错位：鼠标点击使用逻辑坐标、桌面截图却使用物理像素，导致 150% 缩放下截图位置偏到左上方并采到终端窗口。程序现在会在创建窗口前启用每显示器 DPI 感知，让点击、校准和截图统一使用物理像素；自动识别也会优先按当前显示器缩放比例搜索。旧校准会自动清除，升级后只需重新自动识别或手动校准一次。

0.2.13 版本把控制窗口和手动校准向导按 Windows 显示比例同步放大，恢复到启用 DPI 修复前的视觉尺寸；该变化只影响工具界面，不改变游戏截图、识别和点击坐标。

0.3.0 版本实现完整冷启动：自动查找 `TaskBarHero.exe` 的 Unity 游戏窗口；自动判断英雄背包和魔方是否已经打开；必要时发送 `Tab`、识别唯一黄色魔方图标并点击；随后识别所有合成按钮、清空九宫格并采集基准。每轮开始时都会重新准备界面并刷新按钮坐标，不再要求用户提前打开窗口或手动把游戏切到前台。

0.3.1 版本修复冷启动时把游戏场景底部的大块黄色图案误认成魔方入口的问题：入口识别现在会同时限制尺寸、形状、填充密度和垂直位置；未发现可靠入口时会先按 `Tab` 打开英雄背包再重新识别。缺少合成窗口时的检测速度也得到改善，自动准备失败会作为可读的安全暂停报告，不再显示“未处理异常”。

0.4.0 版本删除九宫格识别、空格基准采集和相关诊断逻辑。是否合成完全由游戏合成按钮的蓝色激活状态决定；自动填充后最多等待 3 秒，并要求连续两次识别为蓝色。0.3.x 已保存的按钮位置可自动迁移，不需要重新校准。

0.4.1 版本兼容实心金黄色魔方入口：同时支持旧截图中的黄色轮廓和当前画面中的实心魔方，并结合深棕色圆形按钮底座进行确认，避免把游戏场景里的黄色图案重新误认成入口。

0.4.2 版本修复底部功能栏的宝箱、铁砧和交叉武器也被当成黄色入口的问题。程序会识别前三个等距排列的金色功能图标，推导并复核第 4 个魔方按钮；魔方内部被深色线条分割成多个黄色区域时也可以正确定位。

0.4.3 版本修复透明 Unity 游戏窗口的误遮挡提示。游戏已经处于前台并临时置顶时，Windows 命中测试可能仍返回透明区域下方的资源管理器；程序现在会区分这种正常的透明穿透和真正的其他置顶窗口，后者仍会禁止点击。

0.4.4 版本修复较小有效界面比例下黄色功能图标仅差数个像素便被淘汰的问题。黄色魔方入口现在覆盖支持范围内的多尺度图标，并继续通过前三个等距功能图标和棕色按钮底座安全复核。每次自动准备界面都会保存阶段截图，并在日志中记录程序版本、客户区尺寸、屏幕分辨率、窗口 DPI、显示缩放以及每个黄色区域的候选或淘汰原因。

0.4.5 版本把总日志和每次运行的诊断截图改为保存到启动文件所在目录。直接运行源码时位于 `taskbar_hero.py` 旁边；运行 EXE 时位于 EXE 旁边。若该目录不可写，则安全回退到原来的本机应用数据目录。

0.4.6 版本修复“自动填充”文字覆盖按钮中心像素时被棕色预筛选误杀的问题。预筛选现在核对中心周围多个采样点，最终仍以整块按钮的棕色比例作为安全校验；文字识别失败时不再盲目二次点击魔方入口，避免关闭已经成功打开的合成面板。

## 从源码运行

需要 Python 3.11 或更高版本；运行时只使用 Python 标准库。

```powershell
python taskbar_hero.py
```

运行时不需要安装第三方 Python 库。

## 构建单文件程序

安装 Python 后，在项目目录运行。推荐直接双击 `build.cmd`，或在命令提示符执行：

```bat
build.cmd
```

也可以在 PowerShell 中执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

不要在 CMD 中直接输入 `build.ps1`；CMD 不认识 PowerShell 语法。

脚本会在项目内创建独立构建环境并安装 PyInstaller，最终程序位于：

```text
dist\TBH-AutoSynth.exe
```

把该 EXE 复制到第二台电脑即可；首次启动仍需完成该电脑自己的校准。

如果项目内残留的 `.venv-build` 指向已经卸载的 Python，构建脚本会只删除并重建这个构建环境，不影响源码和配置。

## 项目结构

```text
taskbar_hero.py          程序入口
tbh_automation/app.py   窗口、校准和任务调度
tbh_automation/engine.py 合成状态机
tbh_automation/windows.py Windows 截图、识别和鼠标操作
tbh_automation/autodetect.py 自动位置识别
tbh_automation/model.py 配置模型
tests/                   自动测试
build.cmd / build.ps1    Windows 打包脚本
```

## 测试

```powershell
python -m unittest discover -s tests -v
```

自动测试覆盖多比例和奇数像素位置识别、按钮由灰变蓝、持续灰色超时、连续蓝色确认、合成后再次自动填充、首次灰色后复核成功、类别切换、安全上限、暂停取消、5 小时间隔和配置迁移。

## 注意事项

- 画面识别依赖合成按钮的蓝色外观。游戏主题、分辨率、窗口尺寸或界面比例变化后请重新校准。
- 自动鼠标操作不等于游戏官方许可，也无法保证不触发游戏规则或反作弊。请自行确认并承担使用风险。
- 总日志位于程序运行目录下的 `automation.log`，会自动轮换保留历史记录。每次启动的独立日志和识别截图位于同目录的 `diagnostics\日期时间\`，可直接打包该目录用于分析；单次会话最多保存 200 张合成按钮状态截图。运行目录不可写时才回退到 `%LOCALAPPDATA%\TaskbarHeroAutoSynth\`。
